## 1. 总览

**目标**：先在一个月内交付一个“个人可独立使用”的 A 股日频量化工作台——能看行情、能跑可信回测、能手动模拟下单、能开启定时自动化、能查全部日志，**断网也能演示**；随后进入 **M6 策略研究增值（Phase 2）**，按用户目标“**以盈利为目标的选股与自动交易系统**”提供**选股与推荐（远期价值型 / 近期异动型两条线）+ 异动雷达 + 自选池管理 + 策略研究（ML/walk-forward 样本外）+ 全市场筛选（F14/F15）**（只提供工具与信号，**不承诺收益**）。

| 里程碑 | 主题 | 任务数 | 建议轮次 | 预计人日 | 当前状态（2026-10-25） |
|---|---|---:|---|---:|---|
| **M0** | 骨架：能启动、能建库、能记录 | 10 | R1–R2 | 5 | ✅ 已交付，退出复核通过（见 `REVIEW_M0_R1.md` v1.1） |
| **M1** | 研究闭环：数据 + 策略 + 回测 | 16 | R2–R4 | 9 | 🚧 进行中（真实数据/回测报告/UI 接线） |
| **M2** | 交易闭环：模拟盘 + 手动下单 + 风控 | 12 | R3–R4 | 7 | ⏳ 未开始 |
| **M3** | 自动化：定时任务 + 通知 | 10 | R5 | 6 | ⏳ 未开始 |

| **M5** | 打磨：视觉 + 报告 + 演示 + 手册 | 7 | R7 | 4 | ⏳ 未开始 |
| **M6（Phase 2）** | 策略研究增值：推荐/异动雷达/自选池/样本外研究 + 短线模型 v2 + **全市场筛选（F14/F15）** | 17 | R8 | ≈ 13.5 | ⏸ **暂停**（研究结论不可用；见 §8.5） |
| **合计** | — | **80** | R1–R8 | ≈ 48–53 | — |

> 轮次定义见 `TASKS.md` §4.3（R1 首批并行 → … → R7 打磨 → **R8 Phase 2 策略研究增值**）。一个轮次 ≈ 2–3 个工作日。

**关键路径**：`M0-03 → M0-04 → M2-05 → M2-06 → M3-02 → M4-06 → M4-07`；**M6 关键路径**：`M6-02 表结构 → M6-01 自选池 → M6-03 推荐引擎 → M6-08 样本外验证 → M6-09/10 UI 接线`。任何一环卡住，交付日期直接顺延，Lead 需优先保这条链。

**人力**：Dev1（基础设施+数据）、Dev2（策略+回测+研究）、Dev3（交易+自动化+UI）、QA（测试）、Integrator（装配/文档/脚本），Lead 负责契约评审与最终验收。MVP 阶段 Dev3 负载最重（23/63 项），R4 后视进度决定是否把 UI 页面移交 Dev1/Dev2（`TASKS.md` §4.2）；M6 阶段新增页面与推荐引擎以 Dev2/Dev3 为主。

**GPU / 深度学习说明（重要）**：MVP 全程不需要 GPU，也不引入任何深度学习/机器学习框架。M6 **同样 CPU-only**：ML 排序仅使用可选的 **scikit-learn（CPU，BSD-3）**，**不引入 PyTorch/TensorFlow/JAX 等深度学习框架**；本机 GTX 1650 仅作为将来“远程训练、本地推理”的可选背景硬件，不进入 M6 验收；多因子/ML 全部用 CPU + pandas/sklearn 实现。详见 §11.2。

### 2.3 用户视角验收演示脚本（M0）

> 假设已装 Python 3.12.7 并把项目放在 `quantdesk\`。

1. **检查环境**：打开命令行，执行
   `quantdesk\.venv\Scripts\python.exe scripts\check_env.py`
   → **期望**：输出 Python 版本、每个关键依赖版本、缺失清单；核心依赖齐备时退出码 0。
2. **初始化数据库**：执行 `... scripts\init_db.py`
   → **期望**：中文提示“已创建 22 张表”或“已存在，跳过”；目录下出现 `runtime\quantdesk.db`。
3. **启动界面**：双击 `quantdesk\scripts\start.bat`
   → **期望**：命令行不闪退；浏览器打开 `http://localhost:8501`；左侧导航能看到**终态 12 个页面**（总览/行情/手动交易/策略/回测/持仓/自动化/设置/日志/自选池/今日推荐/全市场筛选；M0 当时为 9 页，Phase 2 增 3 页）。
4. **点一遍页面**：逐页点击
   → **期望**：每页能打开不报错；未开发的页面显示“建设中”说明；设置页能看到环境/依赖状态。
5. **看日志**：操作后打开 `runtime\logs\app-*.log`
   → **期望**：文件存在，每行是 JSON，含时间、级别、消息。
6. **重启验证**：关闭窗口 → 再次双击 `start.bat`
   → **期望**：热启动 ≤ 5 秒；不重复建表、不报错。

### 2.4 预估与风险

- **轮次/人力**：R1–R2，约 5 人日（Dev1 4 + Dev3 1 + Integrator 2 + QA 1，部分并行）。

### 3.3 用户视角验收演示脚本（M1）

1. **拉数据**：打开行情页，选 `600519.SH`，区间“近 1 年”，点“刷新数据”
   → **期望**：出现日 K 线；顶部状态条显示数据源正常与最后更新时间；稍后日志页可看到 `market.bar` 相关记录。
2. **断网演示**（可先做）：把 `config.yaml` 的 `data.provider` 改成 `mock` 并重启
   → **期望**：页面不崩溃，出现“离线演示模式”黄条，K 线仍显示示例数据。
3. **跑第一个回测**：回测页选 `ma_cross`，标的默认自选池，区间近 3 年，初始资金 10 万，点“运行回测”
   → **期望**：几十秒内出结果；KPI 卡显示总收益/年化/最大回撤/夏普/胜率/交易次数；有权益曲线和交易明细。
4. **验证 A 股规则**：把区间选到某只票的涨停日附近，买入选“次日开盘买入”逻辑（策略自动）
   → **期望**：交易明细里没有“涨停价买入”的成交；日志/警告能解释原因。
5. **换策略**：依次跑 `rsi_reversal` 与 `multi_factor`
   → **期望**：三个策略都能出报告；多因子能看到它选出的股票清单（交易明细）。
6. **对比两次回测**：历史回测列表里选两个 run，点“对比”
   → **期望**：指标对比表 + 两条权益曲线叠加。
7. **看可信度提示**：找一个交易次数很少的回测
   → **期望**：警告区出现“交易次数过少/样本过短”的提示（RQ_WARN_*）。
8. **验数据质量**：日志页 → 数据校验报告
   → **期望**：能列出缺失/重复/异常等问题（可用脚本造一条）。

#### M1 验收基线（Lead 首次回测实测，2026-10-25，Mock 数据）

> 用途：M1 验收时用作**量级对照**——同策略/同参数/同数据源下，结果应与基线同量级、且指标方向一致；**不是收益承诺**（Mock 数据仅供演示与回归）。
> 环境：`data.provider=mock`；初始资金 10 万；策略参数取各自默认值。

| 策略 | 总收益 | 最大回撤 | 夏普 | 说明 |
|---|---:|---:|---:|---|
| `ma_cross`（双均线） | **+0.49%** | **-6.23%** | — | 三个策略均成功产出绩效报告与交易明细 |
| `rsi_reversal`（RSI 反转） | **+0.19%** | — | — | 同上 |
| `multi_factor`（多因子） | **+16.88%** | — | **0.62** | 同上，多因子选股逻辑输出正常 |

> 验收判定：①3 个策略均能跑通并出完整指标（AC-F3-06）；②`multi_factor` 夏普 0.62 量级可作为 M1 报告对照；③若同参数重跑结果差异过大（超过 ±20% 相对误差或符号相反），优先排查数据准备区间/复权口径/随机性（策略必须可复现，AC-F3-07），并记录到 `ACCEPTANCE_CHECKLIST.md`。

### 3.4 预估与风险

- **轮次/人力**：R2–R4，约 9 人日（Dev1 3 + Dev2 5 + Integrator 1 + QA 2，部分并行）。
- **风险**：①akshare 改版/限流 → Mock 先行，数据校验兜底；②TA-Lib 装不上 → pandas 兜底，验收按兜底判定；③A 股规则写错（费用/涨跌停/T+1）→ 精确数值单测（AC-F3-03/04）+ QA 独立复核；④回测“好看但失真” → 警告项 + 免责声明，MVP 不承诺盈利。

### 4.3 用户视角验收演示脚本（M2）

> 演示前：账户初始资金默认 10 万（设置页可改）。

1. **看账户**：打开总览页
   → **期望**：总资产 100,000、现金 100,000、持仓 0、当日盈亏 0。
2. **手动买入**：手动交易页搜 `600519.SH` → 方向“买” → 价格默认最新价 → 数量 100 → 看“风控预检”
   → **期望**：预检显示预计金额、费用明细（佣金/印花税/过户费/规费）、成交后仓位占比、风控通过。
3. **确认下单**：勾选二次确认 → 提交
   → **期望**：出现成功提示；今日委托里该单状态“已成交”；持仓页出现 100 股、成本价、市值；总览页现金减少（含费用）。
4. **试 T+1**：立刻在同一页面卖出 100 股
   → **期望**：被拒绝，提示“今日买入不可卖（RK016）”，并显示可卖 0 股。
5. **次日卖出**：设置页/自动化页先“立即运行盘前任务”（做日初结算），再卖出 100 股
   → **期望**：卖出成功；持仓归零；现金回到接近初始值（差额 = 两次费用，可在成交明细核对）。
6. **试风控上限**：把单票仓位上限临时改成 5%（设置页，保存后立即生效）→ 再买 1 万
   → **期望**：被拒绝，提示单票仓位将超限（RK007）并告知可买额度；改回 20% 后恢复；设置页能看到这条修改的审计记录。
7. **试撤单**：下一笔先挂在“未成交”状态（或在回测外用手动挂单场景）→ 点撤单
   → **期望**：撤单成功并释放冻结；已成交的单点撤单会被明确拒绝。
8. **看对账**：重启应用 → 总览页
   → **期望**：无“对账不一致”告警；持仓与现金与重启前一致。

### 4.4 预估与风险

- **轮次/人力**：R3–R4，约 7 人日（Dev3 6 + QA 2，重叠）。

## 8. M6 策略研究增值（Phase 2，用户目标升级）

### 8.1 目标与入口条件

**背景**：用户把项目目标升级为“**以赚钱为导向**”，提出：①推荐自选池；②自选池可自行添加；③找到赚钱办法（多因子/ML/公开方法等）；④为手动/自动下单留接口；⑤关注资金流入大、异动盘（近期线）+ 年化 10–20% 价值型（远期线）。
**用户核心目标（2026-10-26 明确）**：**以盈利为目标的选股与自动交易系统**（短线可盈利 + 全市场筛选）。当前短线模型 v1 已判定 `usable=False`（48 折 OOS 命中率 24.83%≈基础概率、扣费期望 -0.22%、MDD -32.41%，见 `REVIEW_M1.md` §9），因此 **M6-13 短线模型 v2 列为当前 P0**；新增 **F14 全市场筛选 / F15 有效性验证（M6-14/M6-15）同为 P0**。在通过样本外/验证门槛前，短线信号与筛选结果只能“研究阶段”，**不得进入推荐/自动化**。

**M6 目标**：在 MVP 的“执行工具”之上增加 **研究→选股→验证→交易** 闭环：
- **F10 选股与推荐**：远期（价值型，目标年化 10–20% 量级，**研究目标不承诺**）与近期（异动前兆/拉升起爆点）两套可解释榜单；
- **F11 异动雷达**：量比/换手/振幅/涨速/资金流（数据可得）等规则扫描与雷达分；
- **F12 自选池管理**：分组、增删改、CSV/文本导入导出、归一化校验；
- **F13 策略研究**：因子库扩充、ML 排序（CPU）、walk-forward 样本外、参数稳健性；
- **F14 全市场筛选**：全 A（约 5000）分层漏斗（基础剔除→流动性→量价打分→过热剔除→TopN）；as_of 截断、可复现、CSV 导出、200–300 只 ≤5 分钟、显示总数/过滤后/扫描数/数据时间；
- **F15 筛选器有效性验证**：5 分组回测（5/10/20 日收益/超额、单调性）+ RankIC/ICIR + 换手成本 + walk-forward；判定线 RankIC>0.03 且 Top10 日超额>0（扣费后），未过只标“研究阶段/无效”。
- **短线模型 v2（M6-13）**：扩样本、换标签、加市场状态/板块特征、GBDT/排序学习、严格 purge，目标“短线可盈利”（**研究目标，不承诺**）。

**入口条件（硬门槛）**：M1 研究闭环验收通过（3 策略稳定出报告 + 样本外框架可用）且 M2 模拟盘可用；**未满足前只允许做研究页，不接交易**。M6 全部新增契约（5 张表、接口、配置键）已由 Lead 批准（2026-10-25），可实施。

**明确边界（合规 + 算力）**：只提供工具与信号，**不承诺收益**；推荐/研究**默认不自动下单**；**全程 CPU-only，不引入深度学习框架**（ML 用可选 scikit-learn；深度模型留作将来“远程训练/本地推理”的可选扩展，不进入 M6）。

### 11.1 硬件与算力规划（含 GTX 1650）

| 阶段 | 算力需求 | 说明 |
|---|---|---|
| M0–M5（MVP 全部） | **CPU only**，无需 GPU | 依赖：pandas/numpy/TA-Lib（可选）/Streamlit/SQLite；不安装 PyTorch/TensorFlow/scikit-learn |
| **M6（Phase 2）** | **CPU only**，无需 GPU | 额外可选 `scikit-learn`（CPU，BSD-3）用于 ML 排序；仍不安装 PyTorch/TensorFlow/JAX |
| 回测/研究性能 | CPU 单核 | 20 标的 × 5 年 ≤ 15s；walk-forward 3–5 折在分钟级完成；如需更快，用 pandas 向量化而非 GPU |
| 未来可选：深度模型 | 远程 GPU（可选） | 若将来做 LSTM/Transformer，走“远程训练 → 导出权重 → 本地推理”，本机 GTX 1650（4 GB）不作为前置条件；且必须另立里程碑、单独评审 |

### 11.2 为什么 MVP/M6 不需要 GPU / 深度学习（结论）

1. MVP 3 个策略（双均线、RSI 反转、多因子）与 M6 的推荐/异动/ML 排序均为**表格型截面计算**（pandas + 树模型/线性模型），**GPU 无收益**；
2. 引入 DL 框架会让安装体积与失败率大幅上升（用户代码能力弱、要“能直接运行”），与交付目标冲突；
3. 回测/推荐的可信度来自**规则正确（T+1/费用/涨跌停）+ 样本外验证 + 防过拟合**，不是模型复杂度；
4. M6 的 ML 只用 **CPU 版 scikit-learn（可选依赖，缺失降级）**；深度学习属于“将来远程训练”的可选扩展，不进入 MVP/M6 依赖与验收；
5. 本机 GTX 1650 显存有限，不作为任何里程碑的前置条件。
