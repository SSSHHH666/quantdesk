# QuantDesk 术语表（GLOSSARY）

> 版本：v1.1 · 2026-10-25 · 作者：PM（pm-quant）
> 说明：面向**非程序员用户**，每个词给一句“人话解释”，再补它在 QuantDesk 里对应什么。
> 口径与 `docs/SPEC.md` 一致；本表不新增任何规则，只做解释。按 Ctrl+F 搜词即可。

## 0. 怎么用这份表

1. 看界面或日志时遇到不认识的词，先来这里查；
2. 标记为 **「本期不使用」** 的，属于后续版本或参考概念，当前系统不会出现；
3. 标记为 **「系统内部」** 的，是给开发和排障用的概念，普通使用可以忽略。

## 1. A 股交易规则类

| 术语 | 英文 / 缩写 | 人话解释 | 在 QuantDesk 里 |
|---|---|---|---|
| A 股 | A-shares | 中国大陆用人民币交易的股票，我们常说的“沪深股票” | MVP 默认只做 A 股（沪深主板/创业板/科创板）；是否加北交所见开放问题 OQ-2 |
| 交易日 | Trading day | 交易所开门的日子，周一到周五但要排除法定节假日 | 系统按“交易日历”判断，非交易日不跑自动化任务 |
| 集合竞价 | Call auction | 开盘前（9:15–9:25）和收盘前（14:57–15:00）大家集中报价、按“最大成交量”定出一个统一价格的规则 | 系统**不做**盘中竞价微观模拟；日频回测用“次日开盘价”近似 |
| 连续竞价 | Continuous trading | 开盘后 9:30–11:30、13:00–15:00 随时买卖的时段 | 手动下单只在交易时段允许，否则拒绝（RK005） |
| T+1 | T plus one | **今天买的股票今天不能卖，明天才能卖**（“T”是交易日） | 持仓分“总持仓”和“可卖数量”；今天买入的部分可卖数量是 0，卖出会被拒（RK016） |
| 涨跌停 | Price limit | 一只股票一天最多涨/跌多少的硬性限制，按**昨天收盘价**算 | 主板 ±10%，主板 ST ±5%，创业板/科创板 ±20%，北交所 ±30%（北交所本期不交易）；涨停买不进、跌停卖不出 |
| 涨停价 / 跌停价 | Limit up / Limit down | 今天允许的最高价 / 最低价，四舍五入到 0.01 元 | 下单价格超出这个区间会被拒（RK011） |
| 一字板 | One-word limit | 一开盘就封死在涨停（或跌停），全天几乎没有成交 | 保守处理：当天买入委托不成交 |
| ST / *ST | Special Treatment | 被交易所“特别处理”的风险警示股票（*ST 退市风险更高） | 默认**黑名单**，不自动交易、手动也会被拒（RK002） |
| 退市整理期 | Delisting period | 确定要退市的股票在正式退市前的交易阶段 | 默认黑名单，不交易 |
| 整手 | Lot | A 股买入必须是 100 股的整数倍（1 手 = 100 股） | 买 150 股会被拒（RK017）；卖出零股必须一次卖完 |
| 零股 | Odd lot | 不足 100 股的持仓（通常是送股产生） | 卖出时可以一次性卖掉，但不能拆着卖 |
| 科创板 | STAR Market | 代码 688/689 开头的板块，涨跌停 ±20%，买入最少 200 股 | 系统按板块自动套用不同规则 |
| 创业板 | ChiNext | 代码 300/301 开头的板块，涨跌停 ±20% | 同上 |
| 主板 | Main board | 沪市 600/601/603/605、深市 000/001/002/003，涨跌停 ±10% | 同上 |
| 北交所 | BSE | 代码 8 开头/920 开头，涨跌停 ±30% | **本期不交易**（开放问题 OQ-2） |
| 复权 | Adjusted price | 股票分红送股后价格会“跳空”，复权就是把历史价格换算成可比较的连续序列 | 回测默认“后复权”，行情页默认“前复权”，可切换 |
| 前复权 / 后复权 | QFQ / HFQ | 前复权：以现在价格为准往前调（看 K 线顺眼）；后复权：以上市价为基准往后调（算收益不失真） | 前复权用于展示，后复权用于回测 |
| 除权除息 | Ex-rights / Ex-dividend | 分红（发现金）或送股（发股票）后，股价按比例下调 | 系统在“除权除息日”把现金分红记入资金、送股记入持仓，避免虚假涨跌 |
| 停牌 | Suspension | 股票暂时不能交易（如重大事项、核查） | 停牌当天不能下单（RK003），回测里跳过并用最近价估值 |
| 佣金 | Commission | 券商收的交易服务费 | 默认万分之 2.5，单笔最低 5 元；买卖都收 |
| 印花税 | Stamp duty | 国家收的税，**只在卖出时收** | 默认 0.05%（2023-08-28 起减半） |
| 过户费 | Transfer fee | 股票登记过户的费用 | 默认 0.001%，买卖都收（沪深统一） |
| 规费 | Regulatory fee | 交易所/证监系统收的费用（经手费+证管费） | 默认 0.00541%，买卖都收；可合并进佣金展示 |
| 滑点 | Slippage | 理想价格与实际成交价的差距（买卖没人正好按你想的价成交） | 回测默认按 0.05% 不利方向偏移，可配置 |
| 市价单 | Market order | “不管价格，立刻成交”的委托 | **本期默认禁止**（A 股实盘也无真正市价单），配置可开 |
| 限价单 | Limit order | “价格到了才成交”的委托 | 系统默认使用限价单 |
| 价格笼子 | Price collar | 注册制下限制挂单价格偏离现价过大的规则（约 ±2%） | 系统用“价格偏离校验”近似实现，偏离超 2% 拒绝（RK010） |
| 熔断（风控） | Circuit breaker | 亏损达到阈值就“拉闸”，当天不许再买 | 单日亏损 3% 触发，禁止买入、允许卖出，次日自动恢复 |
| 持仓 / 可卖 | Position / Available | 你有多少股 / 今天实际能卖多少股 | T+1 导致二者常常不同，持仓页会分别显示 |
| 资金可用 / 可提 | Buying power / Withdrawable | 能用来买股票的钱 / 能取出来的钱 | A 股卖出资金当天可继续买，但提现要 T+1；本期不做提现 |

## 2. 量化与回测类

| 术语 | 英文 / 缩写 | 人话解释 | 在 QuantDesk 里 |
|---|---|---|---|
| 策略 | Strategy | 一套“什么时候买、什么时候卖”的规则 | 内置 3 个（双均线、RSI 反转、多因子打分），也可新增文件扩展 |
| 信号 | Signal | 策略觉得“该买了/该卖了”的提示，**还没经过风控，不是订单** | 信号经风控 -> 订单；被拦的信号会记为“风控拦截” |
| K 线 / 日线 | Candlestick / Daily bar | 一天的开盘、最高、最低、收盘四个价格画成的蜡烛图 | 行情页展示；数据表 `daily_bars` 存这些 |
| 均线 | Moving Average (MA) | 最近 N 天收盘价的平均线，用来看趋势 | 双均线策略用 MA5 与 MA20 交叉 |
| 双均线 | MA cross | 短期均线上穿长期均线=看涨（金叉），下穿=看跌（死叉） | 内置策略 `ma_cross` |
| RSI | Relative Strength Index | 0–100 的强弱指标：低于 30 常被认为“超卖”、高于 70“超买” | 内置策略 `rsi_reversal` |
| MACD | Moving Average Convergence Divergence | 用两条均线之差判断趋势动能的指标 | 行情页可选副图；本期策略未用 |
| 多因子 | Multi-factor | 同时用多个指标（如动量、波动率）给股票打分排序，买排名靠前的 | 内置策略 `multi_factor`（用 pandas 计算，**不需要 GPU**） |
| 因子 | Factor | 能解释/预测股票收益的特征（如“过去 20 天涨得好不好”） | 多因子策略里用动量与波动率；完整因子库属后续版本 |
| 动量 | Momentum | 过去一段时间涨得好，倾向继续涨 | 多因子打分的第一项 |
| 波动率 | Volatility | 价格上下波动的剧烈程度，越高越“颠” | 多因子打分的第二项（越低越稳，得分越高） |
| z-score（标准分） | Standard score | 把一组数换算成“偏离平均值几个标准差”，便于横向比较 | 多因子打分用它把不同量纲的因子放到同一把尺子上 |
| 调仓 | Rebalance | 按规则定期调整持仓（卖旧的、买新的） | 多因子按 `rebalance_days` 调仓 |
| 回测 | Backtest | 用历史数据“假装”按策略交易，看过去会赚多少 | 回测页核心功能；A 股规则（T+1/涨跌停/费用）全部计入 |
| 绩效报告 | Performance report | 回测结束后的一整套成绩单 | 指标卡 + 权益曲线 + 交易明细 + 警告 |
| 权益曲线 | Equity curve | 账户总资产随时间的走势线 | 回测页/总览页/持仓页都有 |
| 总收益率 | Total return | 期末比期初赚了百分之几 | 回测指标 |
| 年化收益率 | Annualized return | 把收益折算成“平均每年赚多少” | 回测指标（按 252 个交易日/年折算） |
| 最大回撤 | Max drawdown | 从最高点跌到最低点的最大幅度，衡量“最难受的时候有多难受” | 回测指标，越小越好 |
| 夏普比率 | Sharpe ratio | “每承担 1 份风险能赚多少超额收益”，越高越好 | 回测指标（无风险利率按 0 简化） |
| 胜率 | Win rate | 赚钱的交易占总交易的比例 | 回测指标（按平仓交易计） |
| 盈亏比 | Profit factor | 总盈利 ÷ 总亏损，>1 才赚 | 回测指标 |
| 基准 | Benchmark | 用来对照的“大盘”（默认沪深 300），策略该跑赢它 | 回测页可选基准 |
| 交易明细 | Trade list | 每一笔买卖的日期、代码、价格、数量、费用 | 回测页可导出 CSV |
| 样本 / 样本外 | In-sample / Out-of-sample | 用来调参的数据 / 没参与调参、用来最终检验的数据 | **M6 起强制**：回测必须样本外（walk-forward），未通过只能标“研究阶段” |
| 过拟合 | Overfitting | 参数调得太贴合历史，换未来就失灵（像背答案） | **M6 起强制检查**：样本外 + 参数稳健性 + 过拟合风险灯；MVP 阶段用警告提示 |
| 未来函数 | Look-ahead bias | 回测里偷看了“当天还不知道的明天价格”，导致结果虚高 | 策略只能看到截止当天的数据；**M6 增加自动检测**（截断重算比对） |
| 参数 | Parameters | 策略的可调数字（如均线周期 5 和 20） | 策略页表单可改，改完回测/自动化立即生效 |
| 参数寻优 | Optimization / Hyperopt | 自动试很多组参数找最优 | **MVP/M6 均不做自动寻优**（M6 只做手工参数对比与稳健性检查；寻优留 Phase 3） |
| IC / 信息系数 | Information Coefficient | 因子值与未来收益的相关性，衡量因子“准不准” | **M6 可做因子分析参考**（非强制）；完整 IC 分析属 Phase 3 |
| Alpha | 超额收益 | 跑赢基准的那部分收益，也泛指“预测能力” | 参考概念，本期不做因子库 |
| 换手率 | Turnover | 一段时间内买卖的频繁程度 | 回测可看交易次数，完整换手统计属后续版本 |
| 蒙特卡洛 / DSR / PBO | Monte Carlo / Deflated Sharpe / Probability of Backtest Overfitting | 判断“回测好看是不是运气”的统计方法 | **本期不做**，属后续版本（BORROW_MAP B14/B15） |
| 手续费侵蚀 | Fee drag | 交易太频繁时，佣金+印花税把利润吃光 | 预检会显示费用；低于 1000 元的单子默认拒绝，防止最低 5 元佣金吃掉收益 |

## 3. 系统概念类

| 术语 | 英文 / 缩写 | 人话解释 | 在 QuantDesk 里 |
|---|---|---|---|
| 模拟盘 | Paper trading | 用真实行情“假装”交易，不动真钱，用来练手/验证 | MVP 唯一完整的交易方式（`PaperBroker`） |
| 实盘 | Live trading | 用真实资金交易 | **本期不接**，只留适配器骨架 |
| 券商 | Broker | 你开户交易的那家公司；系统通过它的接口下单 | 本期只有模拟券商；未来可接 QMT（需账户） |
| QMT / miniQMT | 迅投 QMT 交易终端 | 国内常见、支持程序化交易的券商终端软件 | 本期只有骨架，调用会提示“未接入”（BR004） |
| 适配器 | Adapter / BrokerAdapter | 一层“翻译”，把系统的订单翻译成某家券商能懂的格式 | `trading/broker.py`；换券商只换适配器，不改业务代码 |
| 订单 | Order | 你发出的“买/卖多少股、什么价”的委托 | 有完整状态：待提交/已提交/部分成交/已成交/已撤/已拒/已过期 |
| 成交 | Fill / Trade | 订单真的成交了的那一笔 | 成交后更新持仓、资金、流水与曲线 |
| 撤单 | Cancel | 把还没成交的委托取消 | 已成交的单不能撤；撤单会释放冻结资金/持仓 |
| 风控闸门 | RiskGate | 所有订单必须经过的“安全检查站”，任何人任何路径都绕不过 | `trading/risk.py`；纯函数，异常时一律拒绝（fail-closed） |
| 拒绝原因码 | Reject reason code | 被拒绝时给的编号，方便查原因（如 RK007=单票仓位超限） | 界面/日志都会显示“中文原因 + RK 码 + 建议动作” |
| RK / BR / DQ / RQ 前缀 | — | RK=风控原因；BR=券商/适配器错误；DQ=数据质量问题；RQ=回测警告 | 详见 SPEC §9.2 |
| 下单服务 | OrderService | 系统里**唯一**允许下单的入口，内部强制走风控 | `trading/order_manager.py`；UI/策略/定时任务都不能直接调券商 |
| 持仓服务 | PortfolioService | 负责记账：买卖后更新持仓、可用数量、成本、现金、流水、资金曲线 | T+1 的“可卖数量”由它维护 |
| 风控参数 | Risk config | 单票上限 20%、总仓位上限 80%、单日亏损熔断 3%、价格偏离 2% 等 | 设置页可改，保存立即生效并留审计 |
| 单票仓位上限 | Position limit | 一只股票最多占总资产的百分比（默认 20%） | 超了买单被拒（RK007） |
| 总仓位上限 | Gross exposure | 所有股票加起来最多占总资产的百分比（默认 80%，即至少留 20% 现金） | 超了买单被拒（RK008） |
| 单日亏损熔断 | Daily loss circuit breaker | 当天亏到 3% 就禁止买入 | 触发时界面红条提示；允许卖出减仓 |
| 黑名单 | Blacklist | 系统或用户禁止交易的股票名单 | 系统自动含 ST/退市整理/新股/停牌；用户也可自己加 |
| 自选池 | Universe | 你关注、系统默认处理的股票集合 | 默认 20–50 只，避免全市场拉数据太慢；设置页可改 |
| 数据源 | Data provider | 行情数据从哪来 | 默认 akshare（公开接口）；无网时用内置 Mock 示例数据 |
| Mock 数据 | Mock / 模拟数据 | 内置的、固定的示例行情，用来演示和测试 | 断网也能跑通全流程；界面上会标“离线演示模式” |
| 离线模式 | Offline mode | 没网时系统自动切换到的状态 | 顶部黄条提示；能看缓存、能跑回测、能模拟交易 |
| 缓存 | Cache | 把拉过的行情存到本地数据库，避免重复下载 | `runtime/quantdesk.db`；增量更新，重复拉不会重复写 |
| 增量更新 | Incremental update | 只补“还没拉过的那几天”，不重新下载全部历史 | 数据层的默认策略 |
| 数据质量校验 | Data quality check | 自动检查数据有没有缺失、重复、异常跳变等 | 报表在日志页“数据校验报告”里；问题码 DQ001–DQ007 |
| 复权因子 | Adjustment factor | 用来把历史价格换算成复权价格的系数 | 数据层保存；缺失时会警告“结果可能失真” |
| 数据库 | Database / SQLite | 本地存数据的“文件柜”，本项目就是 `runtime\quantdesk.db` 一个文件 | 22 张表；备份就是复制/导出这个文件 |
| 备份 | Backup | 把数据库复制一份，防止数据损坏/误删 | 每天自动备份到 `runtime\backups\`，保留 7 份；设置页可手动备份/恢复 |
| 结构化日志 | Structured log | 一行一条、字段固定的日志（JSON 格式），便于机器检索 | `runtime\logs\app-YYYYMMDD.log`；日志页可筛选 |
| 审计流水 | Audit log | “谁在什么时候改了什么”的不可删改记录 | 下单、撤单、改风控、启停自动化、恢复备份都会记 |
| trace_id | 追踪号 | 一次操作/一次任务的唯一编号，用来把相关日志串起来 | 日志页可按 trace_id 过滤，看到完整链路 |
| 事件总线 | Event bus | 系统内部“消息广播站”：发生一件事就通知关心它的模块 | 主题如 `order.filled`、`risk.blocked`、`job.finished` |
| 调度器 | Scheduler / APScheduler | 定时器：每天固定时间自动执行任务 | 盘前 08:50 / 盘中 10:00 / 盘后 15:30（可配） |
| 任务（job） | Job | 一个定时执行的工作单元 | 三个：盘前准备、盘中扫描、盘后总结；有成功/失败/跳过状态 |
| 自动化 | Automation | 让系统按固定时间自己跑策略、下单（模拟盘） | 默认**关闭**，需在自动化页显式开启，可一键停止 |
| 管道 / 管线 | Pipeline | 信号 → 风控 → 订单 → 成交 的自动处理流程 | 自动化页可看到今日各环节数量 |
| 通知 | Notification | 系统主动提醒（成交、任务完成、熔断、报错） | 支持桌面通知/邮件/Webhook，默认可关 |
| Webhook | 网络回调 | 一个网址，系统往它发消息（可接到企业微信/飞书等） | 设置页配置；密钥只放环境变量 |
| 配置 | Config / config.yaml | 系统的参数文件（数据源、费率、风控、调度时间…） | 改参数优先用界面；直接改文件后重启生效 |
| 环境变量 | Environment variable | 操作系统里的“全局设置”，适合放密码 | 密钥类只从环境变量读（`QD_` 前缀），不写进文件 |
| 虚拟环境 | venv / virtual environment | 项目专用的 Python 运行环境，避免和系统里其它项目打架 | `quantdesk\.venv`；`start.bat` 优先用它 |
| 依赖 | Dependency | 项目运行需要的第三方软件包 | 见 `requirements.txt`；`scripts/check_env.py` 可自检 |
| TA-Lib | Technical Analysis Library | 一个算技术指标的现成库，装起来有点麻烦 | 可选；装不上会自动用 pandas 算同样的指标，功能不受影响 |
| pandas / numpy | — | Python 的数据处理基础库（表格、数值计算） | 本期所有计算都基于它们；**不需要 GPU** |
| Streamlit | — | 把 Python 变成网页界面的工具 | 本项目界面框架；启动后浏览器访问 localhost:8501 |
| SQLite | — | 一个“单文件”的轻量数据库 | 本项目存储方案；无需安装数据库服务器 |
| 回测 = 实盘同源 | Backtest/live parity | 回测和实盘用同一套规则和代码，避免“回测赚钱、实盘亏钱” | 规则与费用只实现一次，回测和模拟盘共用 |
| 契约冻结 | Contract freeze | 接口/字段/表名/原因码定下来后不许随便改 | 13 项冻结契约（CF-1…CF-13），改动要 Lead 审批 |
| 里程碑 | Milestone | 项目的阶段目标 | M0 骨架 → M1 研究 → M2 交易 → M3 自动化 → M4 交付 → M5 打磨 |
| 任务编号 | Task ID | 每个开发任务的编号（如 M2-04） | 见 `TASKS.md`，共 63 项 |
| 一键启动 | One-click start | 双击脚本就把环境、数据库、界面都弄好并启动 | `scripts\start.bat` |
| 环境自检 | Environment check | 检查依赖是否装全、版本对不对 | `scripts\check_env.py` |
| GPU / 显卡 | Graphics Processing Unit | 显卡，擅长并行计算（如训练 AI 模型） | **本期完全不需要**；本机 GTX 1650 不参与；不装深度学习框架 |
| 深度学习 | Deep learning (DL) | 用神经网络从大量数据里自动学规律 | **MVP/M6 均不用**；仅远期“远程训练、本地推理”可选，不要求本机 GPU |
| 机器学习 | Machine learning (ML) | 让程序从数据里“学”规律的一大类方法 | MVP 只用基础统计；**M6 可选用 CPU 版 scikit-learn**（BSD-3，可选依赖）；不引入 PyTorch/TensorFlow |
| 训练 / 推理 | Training / Inference | 训练=用数据“学”；推理=用学到的模型“算” | 训练属将来可选项；本期没有训练环节 |

## 3A. Phase 2 新增术语（M6，以赚钱为导向）

> 用户把项目目标升级为“以赚钱为导向”后新增的功能用词。**只提供工具与信号，不承诺收益**。

| 术语 | 英文 / 缩写 | 人话解释 | 在 QuantDesk 里 |
|---|---|---|---|
| 选股与推荐 | Stock screening / Recommendation | 系统每天给出“值得关注”的股票清单，并说明理由 | F10；默认**不自动下单**（加入自选池 → 手动/策略下单） |
| 远期价值型（榜单） | Value / Quality (long-term) | 看便宜不便宜、公司好不好，打算拿几个月到两年的“价值型”清单 | 远期榜（FAR）；研究目标“年化 10–20% 量级”，**不承诺** |
| 近期异动型（榜单） | Breakout / Abnormal momentum | 找“要动/刚开始动”的票，打算做几天到两周的短线机会 | 近期榜（NEAR）；与异动雷达联动 |
| 推荐理由 / 可解释性 | Explainability | 每条推荐必须写清楚“为什么”（哪个因子、多少分位、贡献多少） | 每条 ≥2 条理由 + 因子拆解；无理由不得上榜 |
| 因子贡献 | Factor contribution | 某个指标对最终得分的加分/减分大小 | 推荐理由里的“贡献 +0.21”这类数字 |
| 分位 | Percentile | 在全市场里排百分之多少（92 分位=比 92% 的股票高） | 推荐理由与因子拆解的通用表达 |
| 量比 | Volume ratio | 今天成交量相对最近几天平均的量，>2 常被视为放量 | 异动雷达默认阈值 2.0 |
| 换手率 | Turnover rate | 当天成交的股数占总流通股的比例，越高越“热” | 异动雷达默认阈值 5% |
| 振幅 | Amplitude | 当天最高价与最低价的差幅，衡量波动剧烈程度 | 异动雷达默认阈值 7% |
| 涨速 | Price velocity | 短时间内（如 30 分钟）涨了多少 | 盘中异动规则（需快照数据） |
| 资金净流入 | Net capital inflow | 主力/北向资金当天净买入的金额（数据源提供时） | 近期线/异动雷达的因子之一；缺数据则跳过并标注 |
| 龙虎榜 | Top list (dragon-tiger) | 交易所公布的当日异动/大额买卖席位名单 | Phase 2 数据源可得时作为增强；不可得则不用 |
| 异动雷达 | Abnormal movement radar | 用一组规则扫描“今天哪些票异常”，算出雷达分 | F11；同一标的同类型 3 日内去重 |
| 雷达分 | Radar score | 0–100 的异动强度分（多规则共振越高） | 作为近期榜的重要输入 |
| 自选池 | Watchlist | 你自己关注的股票池 | F12；可分组（远期/近期/观察）、增删改、导入导出 |
| 分组 | Watchlist group | 把自选池按用途分成多组 | 一个标的可属多个分组 |
| 样本内 / 样本外 | In-sample / Out-of-sample (OOS) | 用来调参的历史 / 没参与调参、用来最终检验的历史 | **M6 强制：回测必须样本外**，否则只能标“研究阶段” |
| Walk-forward（滚动验证） | Walk-forward validation | 把历史切成多段：前面训练、后面验证，滚动前进，模拟“当时真能用什么数据” | F13；默认 ≥3 折，训练/验证之间留空档 |
| Purge / Embargo（隔离带） | — | 训练与验证之间空出若干交易日，防止“偷看相邻日子” | 默认 purge=5、embargo=1 个交易日 |
| 参数稳健性 | Parameter robustness | 参数稍微改一改（±20%），结果不能崩 | 红/黄/绿风险灯；不通过标“稳健性不足” |
| 过拟合风险灯 | Overfitting risk light | 用红/黄/绿直观提示“这份结果有多不可信” | 研究页/推荐页展示 |
| 研究阶段 / 可用（模拟盘） | Research-stage / Usable (paper) | 还没通过样本外=研究阶段；通过=可用于模拟盘（仍不自动下单） | 状态徽标；研究阶段禁止接入自动化 |
| UBA | User Bears All（用户自担风险） | “赚亏都是你自己的决定和风险”的声明 | 推荐/交易/报告/关于页固定展示；合规硬要求 |
| 年化 10–20%（研究目标） | — | 远期价值型策略的**研究目标量级**，不是承诺 | 达标口径见 OQ-8；不达标不得宣传 |
| ML 排序 | Machine-learning ranking | 用机器学习模型给股票打分排序 | F13；CPU-only、可选 sklearn；不引入深度学习框架 |
| 标签 / 特征 | Label / Feature | 想预测的目标（如未来 5 日收益）/ 用来预测的输入（因子） | ML 排序的输入输出；必须按时间切分防泄漏 |
| 深度学习 / GPU 训练 | Deep learning / GPU training | 神经网络训练，需要大量算力 | **MVP 与 M6 均不做**；仅远期“远程训练、本地推理”可选 |
